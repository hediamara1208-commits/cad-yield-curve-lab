# Modelling Assumptions

This file lists every financial modelling assumption used by the engine. Update it whenever a convention changes.

## Current model (Phase 0–2): simplified educational model

| Item | Assumption |
|---|---|
| Currency | CAD |
| Face value | 100 per bond |
| Valuation date | A coupon date (t = 0). Accrued interest is zero, so **clean price = dirty price**. |
| Coupon frequency | Annual |
| Maturities | Integer number of years (1 to 5) |
| Day count | None yet: time is measured in whole years |
| Compounding | Annual: `DF(T) = 1 / (1 + z(T))^T` |
| Forward rates | Annually compounded: `f(T1,T2) = [DF(T1)/DF(T2)]^(1/(T2-T1)) - 1` |
| Rate units | Decimals in code (0.035 = 3.5%). Percentages only for display. Basis points: 1 bp = 0.0001. |
| Coupon validation | `coupon_rate` must be in [0, 0.50]. The 50% cap is a **project choice** to catch rates entered in percent (4 instead of 0.04), not a market limit. It cannot catch every unit error: 0.005 typed as 0.5 passes. |
| Settlement | Same-day (no T+1 / T+2 settlement lag) |
| Credit / liquidity | Ignored: all bonds are discounted on a single curve |
| Interpolation | Not needed: exactly one bond per annual maturity |

## Dataset A: synthetic bonds

- Source: generated by us, **not market data**.
- Method: choose a reference zero curve (`data/reference_zero_curve.csv`), compute discount factors, price each bond with `P = sum CF(t) * DF(t)`, round prices to 4 decimals (`data/synthetic_bonds.csv`).
- Purpose: the bootstrap must recover the reference curve. The only expected error comes from rounding the prices (about 1e-6 on discount factors).

## Known simplifications vs. market practice

- Government of Canada bonds pay **semi-annual** coupons and use an Actual/365 day-count convention.
- Real maturities do not fall on whole years, so professional curves need interpolation.
- Professional desks use multi-curve frameworks (e.g. CORRA OIS discounting). Our single bond curve is not equivalent.
